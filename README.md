# Brand Method

Akshat Kavidayal's marketing case-study portfolio. The current public site is [Brand Method](https://brand-method-portfolio.akshatkavidayal.chatgpt.site/), hosted on Sites. This project is not yet connected to a personal GitHub account. The GitHub workflows in this repository are prepared for a future GitHub Pages move and do not currently run.

## Edit the site directly

- Edit the introduction, author name, and LinkedIn URL in `site.json`.
- Edit the five case studies in `content/from-linkedin.json` and `content/studies.json`. Each study has a title, short introduction, facts, analysis, a weakness, a proposed test, limitations, and source links.
- The About page and page layout currently live in `scripts/build.py`; the visual styling lives in `assets/styles.css`. These are code files and need more care when editing.
- After an edit, run `python3 scripts/build.py` to regenerate `dist/`. The current Sites host does not offer a visual content editor for this code-based site. Once the project is on GitHub, the website's text files can be edited in GitHub's browser editor, followed by a reviewed release.

## Research and coordinated publishing

The recurring research task runs Monday, Wednesday, and Friday. It uses free public sources, checks evidence, and prepares a case study, a LinkedIn post with the exact article URL, and an Instagram carousel outline and caption. It must hold a new study as a draft until a coordinated publishing route is ready. No new study should appear on the site by itself.

For a release: review the evidence and all three drafts; publish the website first; verify that the article URL works publicly; publish the LinkedIn post with that URL; publish the Instagram adaptation in the same release session; record the live links. These are separate services, so simultaneous publication means a short coordinated sequence, with any failure reported and retried.

The connected LinkedIn app currently supports professional lookup, not posting. No Instagram publishing account is connected. Both social steps are therefore pending account setup and a supported publishing route. Do not insert fabricated social links or imply a post went live when it did not.

## GitHub setup later

A free GitHub account is useful for storing the site, editing its text files in a browser, and eventually running the prepared research and GitHub Pages workflows. Copilot is optional and not required for hosting, editing, or connecting this assistant to GitHub. The prepared Pages workflow is manual so a content edit cannot silently publish an unmatched case study. If GitHub Pages becomes the main host, use one canonical public URL and update social links to point there.

For GitHub Pages on GitHub Free, the repository must be public. Public repository files and research issues are visible to everyone. After creating a repository, enable Pages with GitHub Actions as the source and test both workflows before relying on them. The existing Sites URL remains the live site until an explicit migration.

## Editorial standards

The five initial studies include two expanded from earlier LinkedIn drafts and three editorial starters. Review them as your own work before sharing them with employers. Use company newsrooms, product pages, public ad libraries, and other free primary materials; link to the original sources. Do not copy campaign imagery or long passages without permission, or claim a campaign caused sales growth without suitable evidence.
